## Массивы (arrays)

**Массив** — это коллекция элементов одного типа **фиксированного размера**. Размер является частью типа массива, поэтому `[3]int` и `[5]int` — это разные типы. Размер задаётся при объявлении и не может изменяться.

```go
var a [5]int              // массив из 5 нулей
b := [3]string{"a", "b", "c"}
c := [...]int{1, 2, 3, 4} // размер вычисляется компилятором
```

**Ключевые особенности массивов:**

-  **Значения (value type)**: при присваивании или передаче в функцию массив копируется целиком.
-   Размер входит в тип, поэтому массивы разной длины несовместимы.
- Память выделяется на стеке (если возможно) или в куче; это контейнер с непосредственным хранением данных.

## Слайсы (slices)

**Слайс** — это динамическая обёртка над массивом, предоставляющая гибкий доступ к последовательности элементов. В отличие от массива, у слайса нет фиксированной длины; он может расти (с помощью `append`).

Слайс описывается **заголовком (slice header)** — структурой из трёх полей:

- `ptr` — указатель на базовый массив,
- `len` — текущая длина (количество элементов, доступных через слайс),
- `cap` — ёмкость (максимальное количество элементов, которые могут поместиться в базовом массиве без перевыделения).

```go
type sliceHeader struct {
    ptr unsafe.Pointer
    len int
    cap int
}
```

Создание слайсов:

```go
// через make
s := make([]int, 5, 10) // len=5, cap=10, заполнен нулями

// литерал
s2 := []int{1, 2, 3}

// срез массива или другого слайса
arr := [5]int{1, 2, 3, 4, 5}
s3 := arr[1:4] // len=3, cap=4 (с 1 по 4 индекс базового массива)
```

**Ключевые особенности слайсов:**

- **Ссылочный тип**: при присваивании или передаче в функцию копируется только заголовок, базовый массив остаётся общим.
- Меняя элементы слайса, мы меняем элементы базового массива, что может затронуть другие слайсы, указывающие на тот же массив.
- Имеют длину `len` и ёмкость `cap`.
- Могут быть `nil` (если не инициализированы) — у такого слайса `ptr == nil`, `len == 0`, `cap == 0`.

## Разница между массивами и слайсами

| Характеристика   | Массив                         | Слайс                                                  |
| ---------------- | ------------------------------ | ------------------------------------------------------ |
| Размер           | Фиксированный, часть типа      | Динамический, может расти                              |
| Тип              | `[N]T`                         | `[]T`                                                  |
| Семантика        | Значение (копируется)          | Ссылка на базовый массив (копируется только заголовок) |
| Длина            | Встроена в тип                 | Определяется во время выполнения (`len`)               |
| Ёмкость          | Нет (совпадает с длиной)       | Есть, может быть больше длины (`cap`)                  |
| Использование    | Редко, для специфических задач | Основной способ работы с коллекциями                   |
| Нулевое значение | Массив нулевых элементов       | `nil` (нет базового массива)                           |
## Нюансы, которые важно знать

### 1. Срезы (slicing)

Слайс можно получить из массива или другого слайса с помощью выражения `a[low:high]`. Важно помнить:

- `low` — включается, `high` — не включается.
- Длина нового слайса = `high - low`.
- Ёмкость нового слайса = `cap(a) - low` (до конца базового массива).
### 2. Функция `append`

`append(slice, elements...)` добавляет элементы в слайс. Если ёмкости достаточно, она записывает элементы в существующий базовый массив и возвращает слайс с увеличенной длиной. Если ёмкости не хватает, выделяется новый массив (обычно с увеличенной ёмкостью), старые данные копируются, и возвращается слайс, указывающий на новый массив.

Поэтому после `append` нужно **всегда присваивать результат**:
```go
s = append(s, newElement)
```

Нюанс: если `append` не привёл к перевыделению, базовый массив может быть общим с другими слайсами, и изменения затронут их. Если перевыделение произошло, старые слайсы не изменятся.
### 3. Передача слайса в функцию

При передаче слайса в функцию копируется заголовок (3 слова), а базовый массив остаётся общим. Поэтому:

- Изменение элементов внутри функции повлияет на исходный слайс (если он указывает на тот же массив).
- Но если внутри функции происходит `append` с перевыделением, исходный слайс не увидит новых элементов, потому что указатель в заголовке исходного слайса остался на старом массиве.
```go
func modify(s []int) {
    s[0] = 100       // повлияет на исходный
    s = append(s, 999) // если cap не хватает, новый массив — исходный не изменится
}
```
### 4. `nil` слайс vs пустой слайс

- `var s []int` → `nil`, `len=0`, `cap=0`, `ptr=nil`
- `s := []int{}` или `s := make([]int, 0)` → не `nil`, `len=0`, `cap=0` (но `ptr` указывает на zerobase)

В большинстве случаев они ведут себя одинаково (например, `len`, `append`, итерация). Различие проявляется при сравнении с `nil` или сериализации в JSON (nil → `null`, пустой → `[]`).

### 5. Копирование слайсов

- `copy(dst, src)` копирует минимальное из `len(dst)` и `len(src)` элементов, не изменяя длину `dst`.
- Простое присваивание `dst := src` копирует только заголовок, оба слайса разделяют один массив.

### 6. Ёмкость и рост

При `append` к слайсу, если ёмкость исчерпана, Go выделяет новый массив большего размера. Алгоритм роста зависит от версии и размера: обычно удваивается до определённого порога, затем растёт медленнее (например, на 25%). Точные детали не гарантируются спецификацией, поэтому не стоит полагаться на конкретный коэффициент.
