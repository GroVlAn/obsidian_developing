В go нет классической реализация ООП, так как он не объектно-ориентированный язык. При этом в go есть свои приближения к этой реализации. Сейчас поговорим об этом конкретнее.

### 1. Инкапсуляция

- **Экспортируемые идентификаторы** (начинаются с заглавной буквы) доступны из других пакетов.
- **Неэкспортируемые идентификаторы** (начинаются со строчной буквы) доступны только внутри своего пакета.

```go
package user

type User struct {
    Name string // экспортируемое поле
    age  int    // неэкспортируемое поле
}

// Экспортируемый метод
func (u *User) GetAge() int {
    return u.age
}

// Неэкспортируемый метод
func (u *User) celebrateBirthday() {
    u.age++
}
```

### 2. Композиция и встраивание (embedding) вместо наследования

В Go нет наследования классов, но есть **композиция** и **встраивание структур (embedding)**. Это позволяет "наследовать" поля и методы другой структуры.

```go
type Animal struct {
    Name string
}

func (a Animal) Speak() string {
    return "..."
}

type Dog struct {
    Animal      // встраивание (embedding)
    Breed string
}

// Переопределение метода
func (d Dog) Speak() string {
    return "Woof!"
}
```

**Особенности:**

- Можно встраивать несколько структур.
- Можно встраивать указатели на структуры.
- При конфликте имён нужно обращаться явно через имя встроенного типа.
### 3. Полиморфизм через интерфейсы

Полиморфизм в Go достигается за счёт **интерфейсов**. Интерфейс определяет набор методов. Тип реализует интерфейс **неявно** (duck typing): если тип имеет все методы интерфейса, он автоматически его реализует. Объявлять реализацию не нужно.

```go
type Speaker interface {
    Speak() string
}

func MakeItSpeak(s Speaker) {
    fmt.Println(s.Speak())
}
```

Полиморфизм работает через интерфейсный тип: мы можем писать функции, принимающие интерфейс, и передавать любые конкретные типы, реализующие этот интерфейс.

**Важно:** интерфейсы в Go маленькие (обычно 1–3 метода). Композиция интерфейсов также возможна:

```go
type Reader interface { Read([]byte) (int, error) }
type Writer interface { Write([]byte) (int, error) }
type ReadWriter interface {
    Reader
    Writer
}
```

### 4. Абстракция

Абстракция также строится через интерфейсы и экспортируемые API. Интерфейс скрывает детали реализации, предоставляя только поведение. Например, можно объявить интерфейс `Repository` и использовать его в бизнес-логике, а конкретная реализация (in-memory, SQL, etc.) подставляется позже.

```go
type UserRepository interface {
    GetUser(id int) (*User, error)
    SaveUser(u *User) error
}

type Service struct {
    repo UserRepository
}
```

## Чего в Go нет (и это нормально)

- **Нет классов** — используются структуры (`struct`) с методами.
    
- **Нет наследования** — вместо этого композиция и встраивание.
    
- **Нет конструкторов** — принято использовать функции-конструкторы вида `NewXxx(...)`.
    
- **Нет перегрузки методов/операторов** — методы должны иметь уникальные имена.
    
- **Нет абстрактных классов** — вместо них интерфейсы + встраивание.
