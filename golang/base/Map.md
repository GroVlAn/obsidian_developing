**Map** — это встроенная в Go структура данных, реализующая **ассоциативный массив** (хеш-таблицу). Она хранит пары «ключ — значение» и позволяет быстро получать значение по ключу.

```go
m := make(map[string]int)
m["apple"] = 5
fmt.Println(m["apple"]) // 5
```

## Создание и инициализация

```go
// 1. Через make
m1 := make(map[string]int)          // пустая map, готова к записи
m2 := make(map[string]int, 100)     // с указанием начальной ёмкости (hint)

// 2. Литерал
m3 := map[string]int{
    "one": 1,
    "two": 2,
}

// 3. nil map (не инициализирована)
var m4 map[string]int // nil map
```

**Важно:** `nil` map можно читать (вернёт нулевое значение и `false` при проверке), но **запись в `nil` map вызовет панику**:

```go
var m map[string]int
fmt.Println(m["key"]) // 0, ok=false
m["key"] = 1          // panic: assignment to entry in nil map
```

## Внутреннее устройство (кратко)

Map в Go — это хеш-таблица с **цепочками бакетов** (bucket). Основные структуры:

- `hmap` — заголовок map: количество элементов, число бакетов, флаги, seed для хеша и т.д.
- `bmap` — bucket: массив из 8 пар ключ/значение и указатель на overflow-бакет.
- 
Алгоритм:

1. Для ключа вычисляется хеш (с использованием случайного seed при создании map).
2. Младшие биты хеша определяют индекс бакета.
3. Старшие биты используются для поиска внутри бакета (tophash).
4. Если бакет переполнен (>8 элементов), создаются overflow-бакеты (цепочка).

При достижении порога заполнения (load factor ~6.5) map **увеличивается** — выделяется новый массив бакетов вдвое большего размера, старые элементы постепенно эвакуируются (lazy evacuation). Это обеспечивает амортизированную O(1) для операций.
