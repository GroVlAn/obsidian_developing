## 1. Массив (Array)

### Описание

Массив — это последовательность элементов **фиксированного размера**, расположенных в памяти последовательно.

Например:

```
[10][20][30][40][50]
  0   1   2   3   4
```
### Основные операции

- Доступ по индексу — **O(1)**
- Изменение элемента — **O(1)**
- Поиск элемента — **O(n)**
- Добавление в конец — если размер фиксирован, невозможно без создания нового массива
- Вставка/удаление в конце — **O(1)**
- Вставка в начало/середину — **O(n)**
- Удаление из начала/середины — **O(n)**
### Где применяется

Массив хорош, когда:

- количество элементов известно заранее;
- нужен быстрый доступ по индексу;
- данные обрабатываются последовательно;
- важна производительность за счёт хорошей cache locality.

### Плюсы

- **O(1) доступ по индексу**.
- Элементы находятся рядом в памяти.
- Хорошая работа CPU cache.
- Простая структура.
- Нет необходимости хранить указатель `next`/`prev`.
- Размер и тип известны компилятору.
### Минусы

- Размер фиксирован.
- Вставка в начало/середину требует перемещения элементов.
- Удаление из начала/середины тоже требует перемещения.
- Если заранее выделить слишком большой массив — часть памяти будет не использоваться.

## 2. Динамический массив / Slice

### Основные операции

- Получение по индексу — **O(1)**
- Изменение — **O(1)**
- `append` — **амортизированно O(1)**
- Вставка в начало — **O(n)**
- Вставка в середину — **O(n)**
- Удаление из начала/середины — **O(n)**
- Поиск — **O(n)**
### Плюсы

- Динамический размер.
- Быстрый доступ по индексу.
- `append` очень удобен.
- Хорошая cache locality.
- Значительно практичнее linked list в большинстве задач.
- Простая работа с памятью.

### Минусы

- При расширении может потребоваться выделение нового массива и копирование.
- Вставка в начало/середину — `O(n)`.
- Slice сам по себе не является непосредственно массивом.
- Несколько slice могут ссылаться на один underlying array, что иногда приводит к неожиданным изменениям данных.

## 3. Односвязный список (Singly Linked List)

Односвязный список состоит из узлов:

```
[10 | next] → [20 | next] → [30 | next] → nil
```
В отличие от массива, элементы списка **не обязаны находиться рядом в памяти**.

Связь обеспечивается указателем `Next`.

### Основные операции

Если у нас есть указатель на нужный узел:

- Вставка после узла — **O(1)**
- Удаление после узла — **O(1)**

Но чтобы найти элемент:

- Поиск — **O(n)**
- Доступ по индексу — **O(n)**

Например, чтобы получить `numbers[500]`, нельзя сразу перейти к 500-му элементу. Нужно пройти список от начала.

### Где применяется

Списки полезны, когда:

- часто происходят вставки/удаления;
- не нужен произвольный доступ по индексу;
- элементы уже представлены связями между объектами.

Например, некоторые специализированные структуры данных могут строиться поверх linked list.

### Плюсы

- Динамический размер.
- Вставка/удаление элемента может быть **O(1)**.
- Не требуется непрерывная область памяти.
- Не нужно заранее знать количество элементов.

### Минусы

- Поиск — O(n).
- Доступ по индексу — O(n).
- Каждый элемент требует дополнительной памяти под указатель.
- Плохая cache locality.
- Работа с указателями сложнее.
- Больше выделений памяти может создавать дополнительную нагрузку на GC.

## 4. Двусвязный список (Doubly Linked List

Похож на односвязный, но каждый узел имеет две ссылки:

```
nil ← [10] ⇄ [20] ⇄ [30] → nil
```
### Основные операции

- Поиск — **O(n)**
- Доступ по индексу — **O(n)**
- Вставка при наличии узла — **O(1)**
- Удаление при наличии узла — **O(1)**
- Вставка в начало/конец — **O(1)** при наличии head/tail

### Где применяется

Хороший пример — **LRU Cache**.

Обычно LRU Cache реализуется комбинацией:

```
Hash Map + Doubly Linked List
```

Hash Map позволяет быстро найти элемент:

```
key → node
```

а linked list позволяет быстро переместить его в начало/конец.

Также может использоваться для:

- undo/redo;
- навигации назад/вперёд;
- deque;
- некоторых кэш-структур.

### Плюсы

- Вставка/удаление — O(1), если есть указатель на узел.
- Можно двигаться в обе стороны.
- Удобно удалять произвольный известный узел.
- Хорошая основа для LRU Cache.

### Минусы

- Два указателя на каждый элемент.
- Больше расход памяти.
- Сложнее реализация.
- Плохая cache locality.
- Поиск всё ещё O(n).

## 5. Хеш-таблица (Hash Table)

Хеш-таблица хранит данные в формате:

```
key → value
```

Именно поэтому поиск по ключу может быть очень быстрым.

### Основные операции

В среднем:

- Search — **O(1)**
- Insert — **O(1)**
- Delete — **O(1)**

В худшем случае:

- Search — **O(n)**
- Insert — **O(n)**

### Где применяется

Практически повсеместно:

```
userID → User
email → User
word → count
IP → information
cache key → cached value
```

### Плюсы

- Очень быстрый поиск в среднем — O(1).
- Быстрая вставка.
- Быстрое удаление.
- Удобно моделирует связь `key → value`.
- Отлично подходит для lookup-операций.

### Минусы

- Нет гарантии O(1).
- Возможны коллизии.
- Требуется дополнительная память.
- Нет естественной сортировки ключей.
- Плохой выбор, если нужно постоянно получать элементы в отсортированном порядке.
- Требуется хорошая hash-функция.


## 6. Дерево (Tree)

Дерево — это иерархическая структура данных.

Например:

```
             A
           /   \
          B     C
        /  \     \
       D    E     F
```

Основные понятия:

- root — корень;
- node — узел;
- edge — связь;
- parent — родитель;
- child — потомок;
- leaf — лист;
- height — высота дерева;
- depth — глубина узла.

Дерево может иметь различные ограничения.

Например, **бинарное дерево**:

> Каждый узел имеет максимум двух детей.

```
       A
      / \
     B   C
```

### Где применяется

Деревья очень часто используются для представления иерархий:

- файловая система;
- DOM;
- AST;
- структура каталогов;
- организационная структура;
- индексы баз данных;
- поисковые структуры.

### Плюсы

- Отлично представляет иерархические данные.
- Можно получить эффективный поиск в некоторых видах деревьев.
- Можно поддерживать данные в отсортированном виде.
- Хорошо подходит для рекурсивных алгоритмов.

### Минусы

- Сложнее массивов и списков.
- Производительность зависит от конкретного типа дерева.
- Несбалансированное дерево может сильно деградировать.
- Рекурсивные алгоритмы могут привести к большой глубине вызовов.
  

# 7. Бинарное дерево поиска (Binary Search Tree)

BST — специальный вид бинарного дерева.

Правило:

```
left subtree < node < right subtree
```

Например:

```
          8
        /   \
       4     12
      / \    / \
     2   6  10 14
```

Если ищем `10`:

```
10 < 8? Нет
10 > 8 → идём вправо

10 < 12 → идём влево

нашли 10
```

### Сложность

Если дерево сбалансировано:

- Search — **O(log n)**
- Insert — **O(log n)**
- Delete — **O(log n)**

В худшем случае:

- Search — **O(n)**
- Insert — **O(n)**
- Delete — **O(n)**

### Где применяется

Когда нужна структура, которая:

- поддерживает порядок;
- позволяет искать;
- позволяет добавлять/удалять;
- может выполнять операции типа min/max/range search.

### Плюсы

- В среднем быстрый поиск.
- Можно хранить элементы в отсортированном порядке.
- Удобно искать диапазоны.
- Min/max можно найти, двигаясь влево/вправо.

### Минусы

- Может выродиться в O(n).
- Реализация сложнее массива/map.
- Требует балансировки для гарантированного O(log n)

## 9. Бинарная куча (Binary Heap)

Например, **Min Heap**:

```
          1
        /   \
       3     5
      / \   / \
     7   8 9  10
```

Главное правило:

```
parent <= children
```

Поэтому минимальный элемент всегда находится в корне.

Max Heap работает наоборот:

```
parent >= children
```

### Важный момент

Heap обычно реализуется не через указатели, а через массив.

Например:

```
[1, 3, 5, 7, 8, 9, 10]
```

Для элемента с индексом `i`:

```
left child  = 2*i + 1
right child = 2*i + 2
parent      = (i-1)/2
```

Это очень хороший момент для собеседования.

### Сложность

- Get Min/Max — **O(1)**
- Insert — **O(log n)**
- Extract Min/Max — **O(log n)**
- Build Heap — **O(n)**
- Search произвольного элемента — **O(n)**

### Где применяется

Главное применение — **Priority Queue**.

Например:

```
Task A — priority 10
Task B — priority 2
Task C — priority 7
```

Heap позволяет быстро получить задачу с максимальным/минимальным приоритетом.

Также:

- Dijkstra;
- A*;
- планировщики;
- Top K;
- Heap Sort.

### Плюсы

- Получение min/max — O(1).
- Вставка — O(log n).
- Удаление min/max — O(log n).
- Компактно хранится в массиве.
- Отлично подходит для Priority Queue.

### Минусы

- Произвольный поиск — O(n).
- Элементы не отсортированы полностью.
- Не подходит, если нужен быстрый поиск конкретного значения.
- Сложнее обычного массива.
